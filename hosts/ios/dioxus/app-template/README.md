# Standalone iOS native renderer probe

Use a separate iOS application target with `main.c` as its entry point. The Rust export starts winit, whose iOS event loop calls `UIApplicationMain`; calling it from the existing SwiftUI `@main` app would run after `UIApplicationMain` and panic. Generate this target with the adjacent `project.yml` and the repo's existing XcodeGen tool.

1. Build `orbital-client-dioxus` with `research-video` for `aarch64-apple-ios` using the research worktree's isolated Cargo target. The feature includes `native` and registers the video renderer for this probe. The `staticlib` crate type adds a link artifact and time to native builds.
2. Create a staging directory **outside the source worktree**. Copy `main.c`, `OrbitalVideoOverlay.m`, and `project.yml` into it. Generate `program.orb` and `language.json` from the TODO fixture using the same research `orb-gpu` export used for the Android probe, and copy those two assets into the staging directory. XcodeGen then packages the assets at the top level of the `.app`, where the Rust host expects them.
3. In that directory run `xcodegen generate --spec project.yml`. Build its `OrbitalNativeGpu` scheme with `xcodebuild -project OrbitalNativeGpu.xcodeproj -scheme OrbitalNativeGpu -configuration Debug -destination 'generic/platform=iOS' ORB_GPU_LIB_DIR=/Users/osamaalghanmi/kflow-native-ui-target/aarch64-apple-ios/debug CODE_SIGNING_ALLOWED=NO build` for a device-target linker check, or set the appropriate development team in Xcode for device installation. `project.yml` links the Rust `.a` by its exact path, disables Xcode's debug dylib mode, and declares the Apple frameworks it uses. The linker check must confirm `_orbital_native_ios_main` is defined in the app executable; a successful Xcode build that links the neighboring `.dylib` instead is not a valid static app proof.
4. Launch on a physical iOS device to verify WGPU pixels, touch, typing, and lifecycle. No physical device is connected to this research machine. The pinned Dioxus Native simulator build currently fails on its CPU renderer's missing `use_wgpu` API; a simulator CPU frame would not prove GPU painting.

This template does not replace the production SwiftUI shell.
